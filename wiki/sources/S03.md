# S03｜NIST SP 800-63B-4: Authentication and Authenticator Management

## 摘要

定義驗證與驗證器管理要求，包含密碼長度、異常時更換密碼、密碼管理器，以及OTP與抗釣魚驗證的差異。WebAuthn可透過綁定驗證者網域提供抗釣魚能力。

## 主張與定位

- S03-C01：服務端若以密碼作為單一驗證因素，至少要求15字元；僅作為多因素驗證之一的密碼可較短，但不得少於8字元。（§3.1.1.2 Password Verifiers；HTML #passwordver）

- S03-C02：驗證服務不應強制定期更換密碼；有證據顯示驗證器遭入侵時，必須要求更換。（§3.1.1.2 Password Verifiers；HTML #passwordver）

- S03-C03：驗證服務不得強制其他密碼字元組成規則，例如一定要混合不同字元類型；應允許至少64字元的最大長度。（§3.1.1.2 Password Verifiers；HTML #passwordver）

- S03-C04：驗證服務必須允許密碼管理器與自動填入；密碼管理器，尤其具產生器者，有助於使用者選擇較強密碼。（§3.1.1.2 Password Verifiers；HTML #passwordver）

- S03-C05：一般密碼、單因素OTP與多因素OTP都不屬於抗釣魚驗證；一次性不等於能抵抗假網站騙取輸入。（§3.1.1 Passwords；§3.1.4 Single-Factor OTP；§3.1.5 Multi-Factor OTPs）

- S03-C06：抗釣魚能力指驗證協定能避免把有效驗證秘密或輸出交給冒牌驗證者，而且不依賴使用者時時警覺。（§3.2.5 Phishing Resistance；HTML #verifimpers）

- S03-C07：WebAuthn可依驗證者已驗證的網域名稱選用驗證秘密，透過驗證者名稱綁定提供抗釣魚能力。（§3.2.5 Verifier Name Binding；HTML #verifier-name-binding）

- S03-C08：是否把WebAuthn驗證器視為多因素，需檢查使用者是否已在本機通過驗證；不能只憑使用WebAuthn就認定具多因素。（Appendix B Implementation Requirements；User Verified (UV)）

## 使用限制

- 這些SHALL/SHOULD主要規範驗證服務與其實作；不等同所有一般網站一律已採用，也不是一般使用者的普遍法律義務。
- 15/8的條件不可省略，也不可解讀成『8字元一定安全』。
- 抗釣魚不是防止所有帳號入侵；裝置或復原流程仍需保護。
- 此標準涵蓋範圍廣，本專案僅選取有明確定位的相關主張。
