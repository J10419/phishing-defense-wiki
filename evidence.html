## 可追溯的內容

[`sources/evidence-cards.json`](../sources/evidence-cards.json)包含六張精選證據卡。每項主張有穩定ID與章節或頁碼，另列適用限制。[`sources/manifest.json`](../sources/manifest.json)保留文獻網址、機構、取得時間及各卡的SHA-256。這些雜湊驗證的是發布的證據卡，不是完整原文。

S02依官方FTC搜尋擷取文字編纂；不宣稱儲存庫保存完整HTML。S07僅使用短引文支持定義，不以此推論攻擊案例或統計。其他卡依所列官方文獻的相關段落編纂；完整版應從官方連結查閱。

Wiki段落引用來源ID並保留定位，來源頁反向連回Wiki。簡報再以Wiki條目為依據，保留逐頁映射。虛構企業IT通知是情境改寫，並非真實事件或有效登入頁。

## 解讀差異

- NIST的密碼15／8字元要求有單因素與多因素的不同條件；FTC的12至15字元建議面向不同讀者，不能直接混為一個規範。
- OTP仍可遭釣魚。HTTPS只描述連線保護，不能單獨判斷服務是否為預期對象。
- 美國來源中的通報與金融規則不是其他地區或組織的通用要求；實際事件應使用所屬組織及服務商的正式流程。

## 更新方式

先取得並核對新版官方資料，再由LLM或編者更新證據卡、Wiki條目與相關連結。若修改證據卡，需同步計算canonical JSON的SHA-256（UTF-8、鍵名排序、不加額外空白）並更新manifest。`ingest`只把已保存的卡片匯入資料庫；`compile`與`rebuild`重播已保存的LLM內容，不會自行擷取網站或呼叫模型。

| Wiki 搜尋 | 搜尋「復原」顯示五個相關條目 |
| 流程頁 320 × 740 | 十個流程節點正常顯示，沒有整頁水平溢出 |
| 瀏覽器錯誤 | 檢查期間未取得 error 等級訊息 |

瀏覽器操作經本機 HTTP 服務驗證。企業通知示例與手機寬度的復原頁亦完成畫面檢視。

重跑資料與結構檢查：

```sh
python scripts/pipeline.py rebuild
python scripts/validate.py
```

來源 URL 與引用定位提供回查路徑；機械檢查只能確認 ID 與連結關係，不能單獨證明語意正確。LLM 編纂與來源核對仍須保留人工判斷。

本地重新生成僅重播保存內容，不代表重新取得來源。瀏覽器的不同視窗尺寸不等同真實手機硬體；未逐一涵蓋所有瀏覽器或列印設備。

# 知識編纂與驗證流程

輸入為官方來源的精選證據卡，輸出為互連 Wiki、可追溯簡報與靜態網站。資料、文字、呈現各自有明確邊界。

```mermaid
flowchart TD
  A[取得官方來源] --> B[驗證格式、正文與引用定位]
  B --> C[Ingest：登錄來源與證據卡]
  C --> D[LLM 編纂 Wiki 與交叉連結]
  D --> E[查詢 Wiki]
  E --> F[整理逐頁內容與來源映射]
  F --> G[核對主張、適用條件與表述]
  G --> H[產生 HTML]
  H --> I[瀏覽器驗證]
  I --> J[發布]
  B -->|來源不符| A
  E -->|證據不足| A
  G -->|引用或內容不足| D
  I -->|呈現或操作失敗| H
```

## 節點責任

1. 來源登錄保留 ID、官方 URL、版本日期、原取得時間與段落定位；內容雜湊用來核對精選證據卡。
2. Ingest 將六份證據卡登錄進資料庫，檢查唯一 ID 與引用關係。
3. LLM 編纂保留來源差異，將內容整理成互連概念。只有此階段產生或修訂知識；本地重建指令僅保存已有產出。
4. 查詢回傳 Wiki 條目與相關來源，缺乏證據時先補來源再改稿。
5. 每張簡報保留 Wiki ID 與來源 ID；渲染程式只處理呈現。
6. 驗證包含本地連結、來源覆蓋、翻頁、情境按鈕、窄螢幕與頁面溢出。

## 回退與停止

失敗只回到負責該問題的節點，修正後重跑受影響的檢查。來源、內容與介面檢查通過後發布。對來源仍有疑問時保留限制，不以模型補寫取代證據。

本機 `rebuild` 執行的是已保存內容的重播；它不會重新抓取官方網站或呼叫 LLM。新來源與實質內容變更需另外經過來源核對及編纂。
